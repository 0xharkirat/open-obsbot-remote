# v1.2 plan — UI redesign + slowest possible motion

Sequel to v1.1.0 (already shipped on GitHub Releases). v1.2 work goes
through PRs per `docs/CONTRIBUTING.md`.

## Theme

> Make the web app feel like the official OBSBOT remote app, but with
> our own features (live preview, sequencer, simple-mode, hold-buttons,
> gimbal grid overlay) and slower motion than OBSBOT Center provides.

## Ground rules

- Reference design: official OBSBOT iOS / Android remote app (their
  PTZ + zoom + preset surface). We're not copying assets, just the
  layout / hierarchy / control density that already works for users.
- All work on `feat/*` / `fix/*` branches, squash-merged to `main`.
- Each PR ships a green smoke battery + touch regression.

## Slowest possible motion (P0 of v1.2)

### Gimbal

Current floor is `MoveSpeed.cinema` → `s_yaw=4 deg/s`. SDK header says
valid range 1..90 but doesn't define behaviour below 1. Empirical
needed.

Plan:
1. New smoke test `tests/slow_motion.mjs`:
   - Send a 90° yaw move at `s_yaw = 0.5, 0.3, 0.1` and `0.0`. Time
     each. If motor jitters or refuses, log SDK return code.
   - Same for pitch.
2. If sub-1 deg/s works without jitter → expose `MoveSpeed.ultra`
   mapping `s_yaw=0.5, s_pitch=0.5, s_roll=0.5`.
3. If sub-1 deg/s fails → use **client-side interpolation**: bridge
   exposes a new `ptz.angle.smooth { yaw, pitch, target_ms }` action.
   Bridge breaks the move into N micro `gimbalSetSpeedPositionR` calls
   at the slowest reliable rate (probably s_yaw=1) over `target_ms`,
   each command shifting target by `(total_delta / N)`. User sees a
   continuous super-slow pan.
4. New tier `MoveSpeed.ultra` exposed in protocol + client + sequencer
   step.

### Zoom

SDK `cameraSetZoomWithSpeedAbsoluteR(zoom_ratio, zoom_speed)`: speed 1
is slowest one-shot; speed 0 is "default", 255 is max. Below 1 doesn't
exist as a parameter.

Plan:
1. **Client-side interpolation in bridge.** New helper
   `cmd_zoom_smooth(target, total_ms)`: at 50ms cadence, sends
   `cameraSetZoomWithSpeedAbsoluteR(intermediate_pct, 10)` stepping
   from current to target over `total_ms`. Each step is small (≈0.01×)
   so motor never jerks.
2. Sequencer + preset recall already pace zoom-speed via
   `zoom_speed_for_duration()`. Wire that into the same interpolation
   for `MoveSpeed.ultra` so zoom moves take 6-15s if user chose ultra.
3. Phone zoom slider: when global move-speed is `ultra`, slider's
   onChanged is treated as a *target* rather than instantaneous;
   bridge interpolates over 4-8s. Slider drag still updates the
   target as you go.

### Estimated user-visible result

| Speed | Yaw rate (90° pan) | Zoom rate (1.0→2.0) |
|---|---|---|
| Instant | <0.5s | <0.5s |
| Fast | ~1s | ~0.6s |
| Medium | ~2s | ~1s |
| Slow | ~5s | ~3s |
| Cinema | ~22s | ~6s |
| **Ultra (new)** | **~3-5min** | **~10-15s** |

Ultra makes a wedding/event 30-second pan look like a deliberate dolly
shot. Sequence step durations ≥30s recommended at ultra.

## UI redesign (P0/P1 of v1.2)

Reference: official OBSBOT iOS/Android app. Goals:
- Preview-first hierarchy. Preview takes the top half on phone-portrait,
  always visible. All controls below.
- Single-row tab bar at the top of the controls: `Joystick / Buttons /
  Presets / Sequencer / Image`. Each tab shows a focused control
  surface; no scrolling needed within a tab on a 6"-7" phone.
- Joystick tab: large pad, zoom slider on the right, hold buttons
  (L/R/U/D) below as a quick-tap alternative.
- Buttons tab: 4-direction pad, mode toggles (AI / HDR / FOV).
- Presets tab: 6 large preset slots with thumbnails (preset zoom + yaw
  badges). Long-press to save.
- Sequencer tab: timeline view. Each step a card with its preset
  thumbnail + duration.
- Image tab: HDR / FOV / Face AE / Face Focus / brightness / contrast
  sliders. **+ exposure mode + EV bias from v1.1's deferred P1-2.**
- Persistent header: device model, latency, move-speed selector
  (Instant / Cinema / **Ultra** / Slow / Medium / Fast).

Skill `flutter-build-responsive-layout` does the breakpoint work.
Skill `design:design-system` produces tokens (color, spacing, type).

### Gimbal grid axis overlay on preview

User asked for visual aid: thin lines over the preview showing the
gimbal's current yaw + pitch zero. Stays still while camera moves so
operators can see "I'm 23° right of center, 8° below horizon."

Implementation:
- New `GridOverlay` widget composited over `PreviewWidget`. Reads
  `state.ptz.yaw` and `state.ptz.pitch`.
- Thin horizontal line at vertical center, thin vertical line at
  horizontal center.
- Two short hash marks where the camera is currently pointed (yaw +
  pitch numbers shown). Color: white at 30% opacity so it doesn't
  obscure subject.
- Toggle in the persistent header (eye icon). Defaults on for
  Advanced mode, off for Simple mode.
- Optional rule-of-thirds gridlines (toggle in Image tab).
